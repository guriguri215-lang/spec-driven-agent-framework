# GitHub Language Policy

Everything committed, pushed, posted, registered, or displayed on GitHub must
be English. This includes documentation, code, identifiers, comments, CLI
text, tests, filenames, branches, commit messages, repository description,
topics, pull requests, issues, reviews, discussions, labels, release notes,
annotated tags, and workflow, job, and step names.

Local Owner reports may use another language, but they must not be copied into
GitHub-facing material. Translate or summarize only after confirming that the
content is publishable.

Before any GitHub action:

1. Audit the tracked candidate set for non-English text and local-only data.
2. Inspect secrets, personal paths, personal identifiers, and generated files.
3. Present the exact target and proposed English metadata to the Owner.
4. Wait for a separate explicit Owner approval.
